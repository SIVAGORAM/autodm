# Meta Instagram login path and migration

## Current repository behavior

HeyLaunch preserves the legacy **Instagram API with Instagram Login** setup and also has an opt-in **Unified Login** path, gated by `META_UNIFIED_LOGIN_ENABLED` (disabled by default):

- OAuth uses `www.instagram.com/oauth/authorize` and the `instagram_business_*` scopes in `backend-nest/src/instagram/instagram.service.ts`.
- The legacy callback exchanges the authorization code for short-lived and long-lived Instagram User tokens, then fetches one Instagram user. Unified Login exchanges the code server-side, discovers the assigned professional accounts, and atomically links the grant within ownership and plan limits. See `backend-nest/src/instagram/instagram.service.ts` and `backend-nest/src/instagram/instagram.controller.ts`.
- `IgAccount` stores one encrypted token and expiry per unique `igUserId`, plus login mode, Meta client business ID, and Unified Login configuration ID. Existing rows default to `INSTAGRAM_LOGIN`. See `backend-nest/prisma/schema.prisma` and `backend-nest/prisma/migrations/20261122100000_unified_instagram_login/migration.sql`.
- Token maintenance refreshes Instagram User tokens with `graph.instagram.com/refresh_access_token` in `backend-nest/src/instagram/token-refresh.service.ts`.
- Media, private replies, direct messages, comment replies, and webhook subscriptions route to the provider host based on each account's saved login mode through `backend-nest/src/instagram/instagram.service.ts`, `backend-nest/src/meta/meta.service.ts`, and `backend-nest/src/queue/dm-processor.service.ts`.
- The webhook decoder already accepts the relevant comment and messaging structures. Each Instagram account retains its own unique row and login mode; webhook processing resolves events to that row's account ID.

## Current Meta guidance

Meta's migration guide says existing Instagram Login integrations continue to work and has no announced end date, but new Instagram API features ship only on Unified Login. Newly created apps cannot configure the older Instagram Login setup. Unified Login is built on Facebook Login for Business, supports login through Instagram or Facebook, and does not require a Facebook Page. [Meta migration guide](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/migration)

Unified Login uses a **Business Integration System User Access Token**, `graph.facebook.com`, `instagram_*` permissions, an Instagram professional account ID returned by `/me/assigned_instagram_accounts`, and an app-level Instagram Webhooks configuration. It requires a business portfolio and a Meta app owned by a business portfolio. Whether the token expires depends on the configuration; access stops if the customer removes the app or moves the Instagram account to another portfolio. [Meta Unified Login setup](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/get-started), [authentication](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/authentication)

**Code-to-documentation check (2026-11-22):** Meta's official [Unified Login setup guide](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/get-started) confirms the `facebook.com/dialog/oauth` URL with `client_id`, `config_id`, `redirect_uri`, `response_type=code`, and optional `prompt=login`; it exchanges the code server-side at `graph.facebook.com/{version}/oauth/access_token`, reads `client_business_id`, and discovers account IDs through `/me/assigned_instagram_accounts`. HeyLaunch uses those endpoints and stores the token server-side, with `META_GRAPH_VERSION` controlling its version. The callback now accepts a complete grant of multiple accounts, validates the list, checks ownership and the user's plan cap, and persists the whole set in one serializable transaction. It then subscribes each account to webhooks and reports partial subscription failures. Each row stores its own encrypted copy of the same business integration token; application operations remain scoped to the selected account ID. If Meta returns a paginated/truncated account list, the callback fails closed rather than silently linking only part of the grant. Token expiry is chosen in the Meta configuration; the dashboard should use the non-expiring system-user option for unattended automation where available. HeyLaunch alerts and requires reconnection for expiring Unified Login tokens. Automatic BISU token management would require `business_management` permission and `appsecret_proof`, so it remains disabled under the current least-privilege scope. [Meta authentication and token storage](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/authentication), [Facebook Login for Business token management](https://developers.facebook.com/documentation/facebook-login/facebook-login-for-business#bisu-token-api)

The required least-privilege scopes for HeyLaunch's current purpose map as follows:

| Current Instagram Login | Unified Login |
| --- | --- |
| `instagram_business_basic` | `instagram_basic` |
| `instagram_business_manage_messages` | `instagram_manage_messages` |
| `instagram_business_manage_comments` | `instagram_manage_comments` |

Meta maps `comments` to `instagram_manage_comments` and `messages` to `instagram_manage_messages` for Unified Login. Advanced Access and Live mode are required to connect customers who are not app roles. Do not request ads permissions for the current product. [Meta permissions](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/permissions), [webhook fields](https://developers.facebook.com/documentation/instagram-platform/webhooks/fields)

**Reels documentation review (2026-11-22):** Meta's current [Instagram Webhooks setup guide](https://developers.facebook.com/documentation/instagram-platform/webhooks/setup) distinguishes Unified Login, Instagram Login, and Facebook Login, documents account subscription for each, and does not list Reels as a limitation. The current [Private Replies guide](https://developers.facebook.com/documentation/instagram-platform/private-replies) explicitly describes the sequence for comments on posts, reels, stories, Live, and ad posts; it says a webhook event is triggered and lists the `comments` field for Unified Login, Instagram Login, and Facebook Login. Current [Business Login for Instagram webhook examples](https://developers.facebook.com/documentation/instagram-platform/webhooks/examples) describe media surfaces including feed, story, or Reel. These are official support evidence for event-driven Reel comment automation across modern login setups. The older [Facebook Login-specific Webhooks page](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-facebook-login/webhooks) still says “Reels are not supported.” That statement is scoped by its URL to the Page-linked Facebook Login setup and conflicts with newer consolidated guidance; it remains a caveat until the selected integration passes live testing. The generic [webhook reference](https://developers.facebook.com/docs/graph-api/webhooks/reference/instagram) field `media.media_product_type` describes payload data, not delivery guarantees by itself. Meta's [IG Media reference](https://developers.facebook.com/docs/instagram-platform/reference/instagram-media/v21.0/) says the `media_product_type` media field is available only with Facebook Login, which does not negate separate webhook examples for Business Login for Instagram.

Meta's Private Replies guide permits one private reply within 7 days of the comment (Live comments only while the broadcast is live); follow-ups require a recipient response and must be sent within 24 hours of that response. Current rate-limit guidance caps post/Reel private replies at 750 calls per hour per professional account. [Private Replies guide](https://developers.facebook.com/documentation/instagram-platform/private-replies), [official rate limits](https://developers.facebook.com/docs/graph-api/overview/rate-limiting/)

## Recommendation

Use existing Instagram Login first because current Meta docs include it and that path avoids changing existing tokens. Keep Unified Login as the strategic path for new accounts; do not switch an existing account's token in place. Before broadly enabling or advertising Reels, run an authorized staging test in both supported HeyLaunch login modes and retain evidence of event delivery, private-reply acceptance, and duplicate handling. Ask Meta for clarification if the Facebook Login-specific limitation affects the setup being tested. Any future migration must preserve the old connection until the new token, webhook subscription, incoming event, and reply are verified. [Meta's migration sequence](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/migration)

## Implementation status and rollout work

1. Unified Login is gated by `META_UNIFIED_LOGIN_ENABLED` and `META_UNIFIED_LOGIN_CONFIG_ID`. The signed, nonce-bound state carries the selected mode; the token exchange is server-side and tokens are not sent to the browser.
2. The Unified flow accepts a complete grant containing multiple assigned professional accounts. It validates IDs and usernames, rejects duplicate or truncated account lists, checks ownership/login-mode conflicts and the plan cap, then persists all accounts in one serializable transaction. Each row contains an encrypted copy of the shared BISU token and the business/config metadata. It subscribes each account to webhooks after commit and reports any partial subscription failure.
3. Account-cap checks run before persistence. Existing rows default to legacy Instagram Login and legacy service calls retain their current host.
4. Account media, messaging, comment replies, and webhook subscriptions route by stored login mode. Token refresh runs only for Instagram Login tokens.
5. Cross-mode reconnect to an already linked `igUserId` is intentionally rejected. The schema still stores one active token, so dual-token overlap and seamless migration rollback for the same account are not implemented. Existing accounts remain unchanged; their migration needs a separate safe workflow.
6. Unified token expiration management is not complete. Configure non-expiring BISU tokens if allowed, or require reconnect; do not rely on automatic refresh until Meta's business token-management flow is implemented and tested.
7. Set up the Unified Login configuration, HTTPS redirect URL, app-level Instagram Webhooks object and only the required permissions in the Meta dashboard. Request Advanced Access for the `instagram_*` scopes and keep the app Live before connecting non-role customers.
8. Staging acceptance requires an authorized professional account and controlled Reel: OAuth, account selection, webhook subscription, new Reel comment delivery, keyword match, commenter ID, private reply, duplicate event, expiry/reconnection, disconnect, rate limits, and recovery. Test Instagram Login and Unified Login independently; capture the API version, granted scopes, subscription confirmation, webhook payload, and provider response. No live provider operation was executed by this audit.

## Current status

Unified Login code support is implemented behind an environment gate for new or same-mode connections. Cross-mode migration, expiring BISU token management, Meta dashboard configuration, App Review, and controlled Reel acceptance remain launch gates. Current official docs support Reel comment webhooks and private replies, but HeyLaunch's integration has not passed an authorized end-to-end Reel test. Reel comment delivery has not been live-verified for HeyLaunch.
